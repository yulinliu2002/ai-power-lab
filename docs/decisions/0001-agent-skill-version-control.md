# 0001 — Version control treatment of `.agents/`, `.claude/`, `skills-lock.json`

## Inventory (verified directly against this checkout)

There are **two independent, differently-provenanced** things living
under `.agents/skills/` and `.claude/skills/`, not one:

1. **`design-taste-frontend`** — declared in `skills-lock.json`:
   ```json
   {
     "design-taste-frontend": {
       "source": "Leonxlnx/taste-skill",
       "sourceType": "github",
       "skillPath": "skills/taste-skill/SKILL.md",
       "computedHash": "6d838b246d0e35d0b53f4f23f98ba7a1dd561937e64f7d0c7553b0928e376c3e"
     }
   }
   ```
   - `.agents/skills/design-taste-frontend/` is a **real directory**
     (not a symlink) containing `SKILL.md` (87,253 bytes).
   - `.claude/skills/design-taste-frontend` is a **symlink** to
     `../../.agents/skills/design-taste-frontend` — a derivative
     convenience link, not independent content.
   - **Verified, not assumed:** `shasum -a 256` of the on-disk
     `SKILL.md` is `aa194351b246b8b4799099d4ed7b033d29eab6e6e3d58d8d2172978be7b3ec89`.
     This **does not match** the lock's `computedHash`
     (`6d838b246d0e35d0b53f4f23f98ba7a1dd561937e64f7d0c7553b0928e376c3e`).
     I could not determine why (different hash algorithm/normalization
     at lock-write time, or the file has drifted since the lock was
     written) — I am not guessing. **The lock's integrity guarantee is
     currently unverified and, by direct comparison, not demonstrated.**

2. **`developing-with-streamlit`** — **not declared in
   `skills-lock.json` at all.**
   - `.agents/skills/developing-with-streamlit` and
     `.claude/skills/developing-with-streamlit` are both **symlinks**
     pointing into
     `.venv/lib/python3.11/site-packages/streamlit/.agents/skills/developing-with-streamlit/`
     — a skill bundled *inside the installed `streamlit` PyPI package
     itself* (this checkout: streamlit 1.65.0).
   - `requirements.txt` pins `streamlit` with **no version
     constraint** (bare `streamlit`). So even this skill's content is
     not actually guaranteed reproducible across machines or time —
     a different `pip install` could resolve a different streamlit
     release with different (or no) bundled skill content.
   - I don't know what process created these two symlinks and cannot
     verify it from repository state alone, so this record does not
     claim a mechanism for them.

## Decision

- **`skills-lock.json`**: recommend **tracking in git**, as the
  declared-dependency manifest for `design-taste-frontend` — the
  closest thing this project has to a lockfile for that one skill.
  This recommendation does **not** claim the hash currently verifies;
  see the unresolved limitation below.
- **`.agents/` and `.claude/`**: **leave gitignored** (already the
  case, via the existing `.gitignore` "Local AI-agent/Claude Code
  tooling" entry, predating this decision). Both the real
  `design-taste-frontend` copy and the `developing-with-streamlit`
  symlinks are machine-local, generated/derived content — not
  something to commit.
- **`developing-with-streamlit`**: no action recommended beyond
  documenting it here. It is not part of `skills-lock.json`'s scope,
  and changing `requirements.txt` to pin `streamlit` is out of scope
  for this decision (not requested, and would touch a shared
  dependency file beyond the PEOS bootstrap).

## Reasoning

Per SPEC-000 §11, the treatment must distinguish a reproducible project
dependency from machine-specific/ephemeral state, and must not be
decided solely by "a file was generated by an installation command."

- Tracking `skills-lock.json` costs nothing and documents intent (which
  skill, from where) even though its hash cannot currently be verified
  against the content it supposedly pins.
- `.agents/`/`.claude/` hold two different kinds of generated/derived
  content (a fetched copy, and symlinks into a `.venv` package) that
  are both machine-local and regenerable, which is why both stay
  ignored regardless of the hash question above.

## Status / Known Limitations

- **Not acted on** — `skills-lock.json` remains untracked as of this
  record; staging/committing it needs the Human Engineering Lead's
  explicit approval (PEOS implementation agents do not commit without
  being asked).
- **Open, unresolved:** `skills-lock.json`'s `computedHash` does not
  match the on-disk `design-taste-frontend/SKILL.md` (sha256,
  verified above). Until this is explained or the lock is
  regenerated, the lockfile should **not** be relied on as an
  integrity guarantee — only as a record of intended source.
- **Open, unresolved:** `developing-with-streamlit`'s reproducibility
  depends on an unpinned `streamlit` version in `requirements.txt`; no
  restoration/reproducibility guarantee is made for it.
